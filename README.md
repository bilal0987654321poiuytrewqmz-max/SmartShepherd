# SmartShepherd AI v0.3 — الراعي الذكي

نسخة معمارية جديدة مبنية على مشروع SmartShepherd السابق، مع إبقاء الكشف الحي محلياً وإضافة Gemini كمشرف سحابي آمن ومحدود الأوامر.

## ما يعمل الآن
- CameraX + تحليل حي `KEEP_ONLY_LATEST`.
- EfficientDet-Lite0 المضمّن فعلياً داخل المشروع: `assets/models/sheep_detector.tflite` (~4.56 MB).
- كشف sheep محلي، ثم IoU tracking مؤقت.
- تخزين عينات JPEG محلياً داخل `filesDir/ai_dataset`.
- سجل نماذج محلي وإطار لإصدارات/ترقية/تراجع النماذج.
- Gemini Supervisor يقرأ telemetry ويعيد أوامر JSON محدودة: تغيير عتبة، حفظ عينة، طلب تدريب، تقييم، أو لا شيء.
- لا توجد حلقة ترسل كل إطارات الكاميرا إلى Gemini.

## خطة النماذج الخفيفة
| الدور | الحجم المستهدف | التشغيل |
|---|---:|---|
| Detector | ~4.6 MB | 8–15 FPS |
| Sheep Re-ID | ~2–5 MB | 1–3 Hz لكل مسار |
| Parts | ~3–7 MB | 1–2 Hz على crops مختارة |
| Attributes | ~2–4 MB | عند الحاجة |
| Behavior | ~1–3 MB | 2–5 Hz على نافذة زمنية |

الهدف العملي للنماذج الأربعة الأساسية: نحو 13–23 MB، مع اختلاف الحجم الفعلي حسب المعمارية والـINT8 والبيانات.

## نقطة مهمة حول التدريب
الكاشف الحالي EfficientDet-Lite0 هو نموذج **استدلال** مضمّن. لا يتم الادعاء بأنه قابل للتدريب على الهاتف لمجرد وجود TensorFlow Lite. لذلك `TrainingEngine` في هذه النسخة يدير dataset/model registry/evaluation lifecycle، لكنه يرفض تعديل الأوزان إلى أن نضيف نموذجاً قابلاً للتدريب مع training signature وloss/preprocessing واختبارات عدم تدهور النموذج القديم.

المرحلة التالية هي إضافة نموذج Re-ID صغير قابل للتدريب فعلياً، ثم إضافة replay buffer وتقييم قبل/بعد وترقية atomic مع rollback.

## دور Gemini
Gemini هو المشرف/العقل التخطيطي، وليس محرك الـgradient. لا يسمح له التطبيق بتنفيذ كود أو تغيير ملفات. الرد يتحول إلى أوامر محددة ومسموح بها فقط.

المفتاح يُحفظ محلياً عبر EncryptedSharedPreferences. وجود المفتاح داخل APK/عميل Android قابل للاستخراج؛ هذا مقبول للنموذج الأولي فقط، أما الإنتاج فيحتاج وسيطاً خادمياً أو مفاتيح قصيرة العمر.

## البناء
- JDK 17
- Android SDK 35
- Gradle 8.9

```bash
gradle assembleDebug
```

لا يحتاج البناء إلى تنزيل نموذج detector من الإنترنت؛ النموذج مضمّن في المشروع.

## الاختبار
الـCI يبني APK ويشغّل اختباراً بسيطاً على emulator. اختبار emulator السابق كان يتعطل أثناء boot على بيئة لا تملك تسريع KVM مناسباً؛ لذلك فشل المحاكي لا يعني أن `assembleDebug` فشل.
